# 보안·계정 동기화 변경과 배포 확인

이 변경은 기존 계정 혼합과 스냅샷 삭제 문제를 막고, 서버가 가입·회원번호와 관리자 권한을 결정하도록 한다. 운영 배포 전 아래 호환성과 실제 기기 검증이 필요하다.

## 데이터 처리

- 로컬 DB는 버전 3으로 올라간다. 게스트와 각 Firebase UID의 번호세트·구매내역을 분리한다. 계정 전환 시 이전 계정의 화면 상태와 비동기 결과를 새 계정에 사용하지 않는다.
- 이전 버전의 소유자 없는 기록은 원본을 보존하여 격리한다. 프로필의 '이전 버전 기록'에서 본인 기록임을 확인한 뒤 현재 인증 계정으로 가져온다. 게스트 기록도 별도 확인 후 가져온다. 잘못된 번호 등 가져오지 못한 원본은 남긴다.
- 로컬에 없는 서버 기록을 삭제하지 않는다. 변경된 행만 전송하며 고정 문서 ID, 로컬 변경 번호, 서버 시각 체크포인트를 사용한다. 삭제는 문서를 지우지 않고 tombstone으로 남기며 삭제된 ID는 재생성하지 않는다. 동일 기록의 일반 수정 충돌은 서버에 마지막으로 수락된 쓰기가 반영되고, 삭제는 수정보다 우선한다.
- 전송 실패 시 변경분은 SQLite에 남고 앱 재개·주기적 동기화·수동 새로고침에서 재시도한다. 업로드 중 새 수정은 이전 요청의 성공 응답으로 지우지 않는다.
- 서버의 구형 Kakao 문서는 검증된 UID와 공급자 조건에 맞을 때만 이전한다. 원본을 남기며 이미 존재하는 대상 문서·삭제 기록을 덮어쓰지 않는다. 중단된 이전은 재시도할 수 있다.
- 구버전이 과거에 다른 사람의 클라우드 경로에 이미 복제했을 가능성이 있는 기록은 자동으로 식별하거나 삭제하지 않는다. 운영 데이터 이력이 필요한 별도 조사 대상이다.

## 서버와 알림

- `registerUser` callable이 인증된 custom-auth UID로 프로필을 생성하고 회원번호를 트랜잭션으로 발급한다. 클라이언트는 회원번호·공급자 등 식별 필드를 변경할 수 없다.
- `manualFetchLotto`는 서버가 발급한 `admin: true` custom claim을 요구한다. 수동 수집·과거 자료 보충은 알림을 보내지 않고 최신 회차를 후퇴시키지 않는다.
- 주간 신규 회차 저장은 통계·개인 알림 처리를 기다린다. 동일 회차 재수집의 중복 알림 시도를 막지만 FCM의 정확히 한 번 전달이나 프로세스 중단 후 자동 재전송을 보장하는 큐는 아니다.
- 개인 푸시는 `users/{uid}/devices/{deviceId}`의 활성 기기만 대상으로 한다. 기존 루트 `fcmToken`은 사용하지 않는다. 로그아웃 전에 기기 연결 해제·토큰 폐기를 시도하고, 둘 다 실패하면 로그인 상태를 유지해 재시도할 수 있게 한다. 로그아웃 중 늦은 토큰 갱신이 재등록하지 못하도록 막는다.
- 알림 설정은 로컬에 먼저 보존하고 실패 상태를 표시한다. 재연결 후 성공하면 대기 표시를 해제한다. 공용 토픽과 개인 기기 알림을 모두 반영한다.
- 피드백 필드·본문 길이·회원 신원은 규칙으로 검사한다. 익명 제출 자체의 호출량 제한과 App Check 적용은 후속 작업이다.
- QR은 정확한 동행복권 호스트만 허용하고 HTTPS로 정규화한다. WebView 이동도 다시 검사하며, 저장 번호는 서로 다른 1~45의 정수 6개여야 한다.

## 배포 순서와 호환성

1. 운영 Firebase 규칙·함수·IAM 설정과 현재 배포 버전을 확인하고 복구 자료를 확보한다. 로컬 소스 백업은 운영 Firestore/사용자 기기 DB 백업을 대신하지 않는다.
2. 테스트 환경에서 새 `registerUser`, 수정된 Functions와 Firestore 규칙을 배포한다. 실제 Kakao/Apple 가입, 기존 계정, 두 기기 동시 편집·삭제, 알림 OFF·로그아웃·오프라인 재시도를 확인한다.
3. 운영에서는 서버와 규칙을 새 클라이언트보다 먼저 준비하되 앱 업데이트와 적용 시점을 함께 조율한다. 새 규칙은 구버전의 식별 정보 쓰기, 루트 FCM 토큰 쓰기, 동기화 문서의 실제 삭제를 거부한다. 새 앱도 `registerUser` 배포 전에는 신규 로그인을 완료할 수 없다. 필요하면 최소 지원 앱 버전 정책 또는 별도의 단계적 전환을 먼저 설계한다.
4. 새 앱이 알림을 허용하고 기기를 등록한 뒤 개인 푸시가 복구되는지 확인한다. 구버전 루트 토큰을 새 코드의 예비 전송 대상으로 사용하지 않는다.
5. 배포 후 권한 거부·가입 실패·동기화 대기·푸시 오류와 호출량을 관찰한다.

앱 DB가 버전 3으로 올라간 뒤 소스/앱 바이너리만 구버전으로 되돌리면 구버전 DB 열기가 실패할 수 있다. 실제 앱 업데이트 이전의 DB 백업 또는 호환 가능한 후속 마이그레이션이 필요하다. 이 수정 작업 자체는 사용자 기기의 DB 마이그레이션이나 운영 배포를 실행하지 않는다.

## 검증

- Flutter: `flutter analyze --no-pub`, `flutter test --no-pub`, `flutter build bundle --debug --no-pub`.
- SQLite 테스트는 실제 SQLite를 사용해 스키마 이전, 원본 보존, 계정 전환, 두 기기 동기화, 삭제 우선, 지연 응답, 재시도를 검증한다.
- 알림 테스트는 FCM/설정/문서 저장소를 대체하여 토큰 회전·해제 실패·계정 변경·늦은 갱신·알림 설정 경합을 검증한다.
- 서버 테스트 재현은 `functions/test/README.md`를 따른다. 실제 Firestore 에뮬레이터에 운영 규칙 파일을 읽혀 권한과 트랜잭션을 확인한다. 운영 프로젝트·실제 푸시 수신자에 요청하지 않는다.
- 디버그 번들 컴파일은 서명한 Android/iOS 배포 빌드나 실제 기기에서의 SDK·푸시·QR 화면 검증을 대신하지 않는다.

## 남은 범위

서버 운영 의존성의 보안 경고 해소, 관리자 HTTP 비밀값의 URL 전달 제거, Kakao 키 제한/중계, 계정 삭제 흐름, App Check·제출 빈도 제한, 공개 회차 중간 누락 복구, 전체 화면 캐시 갱신, 목록·지도 성능과 실제 기기 측정은 별도 후속 작업이다. 이번에는 기존 운영 패키지 버전을 유지하고 회귀 테스트용 개발 의존성만 추가했다.


## 2026-09-22 개발 기기 로그인 보완

- 운영 배포 상태를 조회한 결과 `registerUser`가 없었다. 최신 클라이언트의 로그인 마지막 단계에 반드시 필요한 함수여서 이 함수 하나만 `lottonote-prod / asia-northeast3`에 추가했다. 기존 7개 함수 및 Firestore 규칙은 변경하지 않았다. 배포 전 규칙과 인증 함수 메타데이터를 로컬 작업 폴더에 보관했다.
- 공개 callable 진입점 확인: `createAuthToken`은 빈 자격증명에 `INVALID_ARGUMENT`, `registerUser`는 미인증 요청에 `UNAUTHENTICATED`를 반환한다. 이 확인은 실제 Kakao OAuth 로그인 성공을 대신하지 않는다.
- 카카오톡 로그인 실패 시 계정 로그인으로 전환하고, 사용자가 취소한 경우 추가 로그인 화면을 열지 않는다. iOS에서 OAuth 복귀 URL을 Flutter 화면 경로로 중복 처리하지 않도록 `FlutterDeepLinkingEnabled=false`를 설정했다.
- 기존 Firebase 세션이 있는 업그레이드 사용자는 계정별 회원번호 캐시가 없을 때 서버 등록 함수를 통해 복구한다. 네트워크 오류만으로 유효한 Firebase 세션을 제거하지 않는다.
- 개발 서명 Release 빌드 1.0.4(3)는 Xcode/Flutter 디버거 연결 없이 실행하도록 준비했다. TestFlight 업로드는 하지 않았다.
- 실기기 DB v2의 번호세트 4개·구매기록 11개를 설치 전에 백업했다. 업데이트 후 v4 DB에서 기존 모든 열/행이 소유자 미확정 원본으로 그대로 보존되었고, 인증 계정 기록은 별도로 동기화된 것을 확인했다.
- 회원 등록 함수 외 나머지 보안 규칙·알림 서버 변경은 여전히 별도 배포 조율 대상이다. 특히 구형 운영 알림 서버는 신규 기기별 토큰을 사용하도록 아직 업데이트되지 않았으므로 신규 앱의 개인 푸시는 이번 작업에서 완료 검증하지 않았다.

참고: [Kakao 로그인 구현 예제](https://developers.kakao.com/docs/ko/kakaologin/flutter), [Flutter 플러그인 딥링크 설정](https://docs.flutter.dev/ui/navigation/deep-linking).
