# 추첨 결과 수집

추첨 시각은 방송 편성에 따라 늦어질 수 있다. 시각만으로 결과 발표 완료를 판단하지 않는다.

- `fetchWeeklyLotto`: 토요일 20~23시 5분 간격 실행. 실제 신규 회차 조회는 한국 시간 20:35부터 시작한다.
- `updatePrizeStores`: 매일 매시 07·37분 실행. 누락 번호 수집과 최근 두 회차의 당첨금·판매점 보완을 함께 수행한다. 자정이나 주 경계에서도 복구를 계속한다.
- 기준 회차는 1회 추첨일(2002-12-07)과 한국 시간으로 계산한다. 저장된 최신 회차에 1만 더하고 끝내지 않고, 기준 회차까지 누락분을 순서대로 채운다. 실행당 최대 3회차로 제한하고 다음 실행에서 이어간다.
- 선택된 회차·추첨 날짜·서로 다른 6개 번호·별도 보너스 번호를 검증한다. 검색 결과의 다른 회차, 드롭다운 항목, 다른 영역의 공은 저장하지 않는다.
- 일부 당첨금/판매점만 게시된 응답으로 기존 정보를 지우지 않는다. 모두 0인 당첨금 표는 집계 완료로 취급하지 않는다.
- 저장은 기존 Firestore 트랜잭션을 사용한다. 최신 회차를 역행시키지 않고, 과거 회차 복구와 반복 실행은 결과 알림을 재발송하지 않는다.
- 결과가 12시간 이상 미확인 상태면 누락 회차당 관리자 알림을 한 번 시도하고 재수집을 계속한다.

## 2026-10-04 장애 확인 및 복구

1243회 문서의 추첨일은 2026-09-26, 서버 저장 시각은 2026-10-03 20:45 KST였다. 1244회 문서는 없었다. 20:45 시작 후 20분간만 재시도하는 기존 작업과 ‘저장 최신 + 1’만 수집하는 방식이 결합해 수집이 한 주 밀렸다.

1244회(2026-10-03)의 번호 1, 13, 18, 26, 34, 38 / 보너스 25를 검증해 서버에 복구했다. 최신 메타와 해당 회차 통계도 갱신했으며 복구 알림은 발송하지 않았다.

단위 테스트: `cd functions && npm test` (2026-10-04: 22개 통과)

배포 범위: `firebase deploy --only functions:fetchWeeklyLotto,functions:updatePrizeStores --project lottonote-prod`

앱은 기존 서버 동기화로 결과를 받는다. 이 변경을 적용하는 데 앱 재배포는 필요 없다. 원문 사이트 자체의 장애나 HTML 변경 시에는 검증 실패로 보류하며 운영 로그를 확인해야 한다.
