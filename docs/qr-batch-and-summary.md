# QR 일괄 등록과 회차별 결과 확인

이번 변경은 여러 복권을 한 번에 등록하고, 실제 추첨 결과가 도착한 뒤 확인 상태를 기록하는 흐름이다. 앞선 보안·계정 동기화 변경 위에 추가한다.

## 사용 흐름

1. 홈의 **복권 여러 장 등록**을 연다. 카메라를 유지한 채 여러 QR을 읽거나, 사진을 여러 장 선택한다.
2. 대기 목록에서 회차·게임 수·번호를 확인한다. 잘못 추가한 항목은 제거한다. 필요한 경우 동행복권 결과 화면을 열어볼 수 있다.
3. **N장 등록**을 누르면 전체 목록을 SQLite 트랜잭션으로 저장한다. 실패하면 화면과 대기 목록을 유지하여 다시 시도할 수 있다. 저장 전 뒤로 나가면 목록 폐기 여부를 확인한다.
4. 홈의 **내 복권 한눈에**에서 회차를 선택한다. 실제 당첨번호가 없는 기록은 추첨 또는 결과 업데이트 대기로 남는다. 당첨번호가 도착하면 앱을 다시 열지 않아도 결과 미확인 상태로 갱신된다.
5. **구매 결과** 화면에서 번호·등수를 살펴보고 결과 확인 완료 버튼을 누른다. 구매내역에서도 각 기록을 확인 완료로 표시할 수 있다. 화면을 열었다는 이유만으로 자동 확인 처리하지 않는다.

수동 입력도 동일하게 요약·확인 기능을 사용할 수 있다. 수동 입력 한 묶음은 화면상 한 장으로 집계된다. 확인 완료는 사용자가 결과를 확인했다는 뜻이며 당첨금 수령이나 구매 진위 확인을 의미하지 않는다.

## 데이터와 중복 처리

- SQLite v4는 기존 기록을 유지하며 `qr_fingerprint`, `result_checked_at`을 추가한다. 기존 미확인 기록은 미확인 상태로 시작한다.
- QR의 전체 토큰을 SHA-256 지문으로 변환한다. 원본 QR URL/토큰은 이 새 구매내역에 저장하거나 동기화하지 않는다. 번호가 같은 별도 복권도 전체 QR 토큰이 다르면 별개 기록으로 취급한다.
- 같은 계정에서 같은 QR을 여러 번 저장하거나 여러 기기에서 동시에 등록해도 고정 원격 ID로 하나의 기록에 수렴한다. 계정이 다른 기록은 서로 조회하거나 중복 판정하지 않는다.
- 이전 기능에서 저장한 QR 기록은 원본 토큰이 없으므로 지문을 소급해서 만들 수 없다. 번호만으로 과거 기록과 합치거나 지우지 않는다.
- 기존 삭제 우선 정책을 유지한다. 한 번 삭제된 QR 기록은 재스캔으로 자동 복원하지 않으며 안내 문구를 보여준다.
- 확인 상태는 기기 간 동기화된다. 오래된 미확인 쓰기가 이미 존재하는 확인 상태를 지우지 않도록 병합한다. 일반 동기화 실패 시 변경분은 기기에 남는다.
- 공개 추첨 결과 갱신과 계정별 기록 갱신 신호를 분리했다. 홈과 구매내역의 회차 결과를 묶어서 읽으며, 알림 설정 실패가 공개 결과 갱신을 막지 않도록 실행 순서를 조정했다.

## 검증과 배포

새 테스트는 QR 유효성·연속 인식·중복/제거·여러 사진·저장 실패·뒤로 나가기·카메라 생명주기, SQLite v3→4 이전·원자적 저장·계정 전환·두 기기 수렴·확인 상태 충돌, 홈에서 새 추첨 결과 반영과 확인 화면 저장 흐름을 포함한다.

화면 테스트는 작은 화면과 큰 글씨, 밝은/어두운 테마를 검사한다. 카메라와 사진 인식은 대체 입력으로 검증하므로 실제 Android/iPhone의 카메라 권한·종이 QR 인식·사진 선택·동행복권 WebView는 출시 전에 기기에서 확인해야 한다. 디버그 번들 컴파일은 서명한 배포 빌드나 스토어 제출을 대신하지 않는다.

선택적 화면 미리보기는 테스트 실행 시 `QR_PREVIEW_PATH`, `PURCHASE_PREVIEW_DIR`, `FLUTTER_PREVIEW_SDK` Dart define을 제공해 생성한다. 일반 테스트 실행은 미리보기 파일을 만들지 않는다.

새 서버 함수는 추가하지 않는다. 앞선 수정의 `registerUser`·Functions·Firestore 규칙 배포 조건과 구버전 호환성은 `security-sync-rollout.md`를 따른다. 운영 서버나 실제 사용자 기기 DB는 이 개발 작업에서 변경하지 않는다. 기기 DB가 v4로 올라간 뒤 앱만 구버전으로 되돌리는 방식은 지원하지 않는다.

월별 지출·한도, 홈 화면 위젯, 번호 조건 프리셋과 계정 삭제 기능은 이번 추가 기능 범위에 포함하지 않았다. 특히 계정 삭제는 스토어 출시 준비 단계에서 별도로 마무리해야 한다.
